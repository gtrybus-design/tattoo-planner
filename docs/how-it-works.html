Chapter 1

Two halves: a slow builder and a fast player

The project is split into two programs that never run at the same time. Python does the heavy, one-off work: reading anatomy, fitting a rig, building skin, working out weights. It writes everything the browser needs into one data file. The browser then only does what has to happen every time you move a joint.

Python · build once

tools/fit_rig.py and friends

Runs in the terminal and takes about a minute or more. Uses numpy (fast maths on big arrays) and sometimes scipy and libigl.

  • Reads the Z-Anatomy skeleton and muscles
  • Moves a ready-made rig's joints onto the real joints
  • Builds fat and skin around the muscles
  • Works out how much each bone moves each point

body-rig.js
Browser · every pose

index.html

Opened in Chrome. Uses three.js (a 3D drawing library loaded from the internet) and plain JavaScript.

  • Turns the data back into 3D meshes
  • Lets you drag body parts, within real joint limits
  • Moves muscles, fat and skin with the bones
  • Keeps them out of the bones and each other

The data file is the contract between the two halves. fit_rig.py ends by writing window.BODY_RIG = {…}, and index.html loads it with a plain <script src="body-rig.js">. Because it's a script, not a fetched file, the page works when opened straight from disk (file://) with no web server.

Why it matters to you: if a change is about the body's shape at rest, such as fat, skin thickness, the face or the hands, it belongs in Python and needs a rebuild. If it's about how things move, such as joint limits, collisions or presets, it's usually in index.html, and a browser refresh shows it.

Lesson 1

Scripts, imports and the command line

Every tool in tools/ is a script: a file Python runs from top to bottom. The first lines bring in other code (imports) and read what you typed after the file name in the terminal (command-line arguments).

tools/fit_rig.py · top · tools/tissue_depth.py · bottom
import os, sys, re, json, struct, base64, gzip, pickle
import numpy as np

sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))
from meshes import read_meshes

src, glb_path, out = sys.argv[1:4]

# ... and at the bottom of tools/tissue_depth.py:
if __name__ == '__main__':
    import sys
    for k, (d, n, st) in depths(sys.argv[1]).items():
        print(f'{k:4s} {MIDLINE.get(k, BILATERAL.get(k)):24s} {d * 1000:5.1f} mm  ({st}, n={n})')
  • import numpy as npLoads a library and gives it a short nickname. Everyone writes np for numpy, so copied examples work.
  • sys.path.insert(0, …)Adds the tools/ folder to the places Python looks for modules, so from meshes import read_meshes finds tools/meshes.py no matter which folder you run from.
  • sys.argv[1:4]The words typed in the terminal, as a list. Item 0 is the script's own name, so [1:4] takes the next three, and src, glb_path, out = … unpacks them into three names in one line.
  • if __name__ == '__main__':True only when the file is run directly. fit_rig.py does import tissue_depth and uses its depths() function; the block at the bottom only runs when you type python3 tools/tissue_depth.py file.csv to see the table. One file, two jobs: library and tool.

Use it anywhere: put the reusable parts of a script in functions and the "run me" part under if __name__ == '__main__':. Then other scripts, notebooks and tests can import the functions without kicking off the whole program.

Also worth copying: the project keeps its extra libraries (scipy, libigl, pillow) in a private virtual environment, .venv/, created with python3 -m venv .venv and filled with .venv/bin/pip install …. Each project gets its own versions and nothing leaks into the rest of your Mac. The -I in python3 -I ("isolated") stops Python picking up stray modules from the current folder.

Lesson 2
Functions, docstrings and default values

          
A function packages a few lines under a name, takes inputs and hands back a result. tissue_depth.py has two short ones that show nearly everything you need.

          
tools/tissue_depth.py

          
def shorth(v):
    """The mean of the shortest half of the data (Andrews et al. 1972)."""
    v = np.sort(v); h = len(v) // 2 + 1
    k = np.argmin(v[h - 1:] - v[:len(v) - h + 1])
    return v[k:k + h].mean()


def depths(path, sex='M', min_age=18):
    """{code: (depth in metres, number of people, 'mean' or 'shorth')} for every landmark with data."""
    ...

          
  • """…"""A docstring: the first string in a function says what it returns. Editors show it when you hover the name. Every function in this project has one, and they describe the result, not the steps.
  • sex='M', min_age=18Default values. depths(path) uses adult men; depths(path, min_age=30) changes just one setting by name. Callers only spell out what's different.
  • len(v) // 2 + 1// is whole-number division: 7 // 2 is 3. Half the data, rounded down, plus one.
  • v[k:k + h]A slice: items k up to (not including) k + h. Slices never go out of range; they just stop at the end.
  • return …Hands the value back. A function without return gives back None.

          
Use it anywhere: when data has outliers (one typo of 250 mm in a list of 5 mm depths), a plain mean lies. The project uses the shorth for the skewed landmarks. A simpler cousin is the trimmed mean: sort, drop the lowest and highest few, average the rest. Same idea for grades, prices or sensor readings.

Lesson 3
Dictionaries, comprehensions and f-strings

          
A dictionary maps keys to values, like a lookup table. A comprehension builds a list or dictionary in one line. An f-string drops values into text with formatting. All three appear in a few lines of tissue_depth.py.

          
tools/tissue_depth.py

          
MIDLINE = {'op': 'opisthocranion', 'v': 'vertex', 'm': 'metopion', 'sg': 'supraglabella', 'g': 'glabella', ...}
SKEWED = {'go', 'mr', 'me', 'sm'}      # (shorth instead of the mean)

hdr = rows[2]; col = {h: i for i, h in enumerate(hdr) if h}

stat = 'shorth' if code in SKEWED else 'mean'

print(f'{k:4s} {MIDLINE.get(k, BILATERAL.get(k)):24s} {d * 1000:5.1f} mm  ({st}, n={n})')

          
  • {'op': 'opisthocranion', …}A dictionary: landmark code → full name. MIDLINE['v'] is 'vertex'.
  • {'go', 'mr', …}Curly braces without colons make a set: no order, no repeats, and x in SKEWED is instant even for huge sets.
  • {h: i for i, h in enumerate(hdr) if h}A dictionary comprehension. enumerate gives (position, item) pairs; the result maps each column name to its column number, skipping blank names. After that, r[col['Sex']] reads the Sex column without hard-coding "column 7".
  • a if cond else bA one-line if/else that produces a value.
  • .get(k, default)Like [k], but returns the default instead of crashing when the key is missing.
  • {d * 1000:5.1f}Inside an f-string, anything after : is a format: 5.1f means 5 characters wide, 1 decimal. 24s pads text to 24 characters, which lines the table up.

          
Use it anywhere: look columns up by name, never by number. The day someone adds a column to the spreadsheet, code that says r[7] silently reads the wrong data; code that says r[col['Age (yrs)']] keeps working.

Lesson 4
Reading messy real-world data

          
Published data is never clean. The C-Table has 1,971 people from 19 studies, with blank cells, ages written as text, and two columns (left, right) for some landmarks. This loop survives all of it.

          
tools/tissue_depth.py · depths()

          
rows = list(csv.reader(open(path, encoding='latin-1')))
hdr = rows[2]; col = {h: i for i, h in enumerate(hdr) if h}
out = {}
for code in list(MIDLINE) + list(BILATERAL):
    cols = [col[code]] if code in MIDLINE else [col['L_' + code], col['R_' + code]]
    vals = []
    for r in rows[3:]:
        try: age = float(r[col['Age (yrs)']])
        except ValueError: continue
        if r[col['Sex']] != sex or age < min_age: continue
        for c in cols:
            if r[c].strip():
                try: vals.append(float(r[c]))
                except ValueError: pass
    if not vals: continue
    v = np.array(vals)
    stat = 'shorth' if code in SKEWED else 'mean'
    out[code] = ((shorth(v) if code in SKEWED else v.mean()) / 1000, len(v), stat)
return out

          
  • csv.reader(open(path, encoding='latin-1'))The csv module splits rows correctly even when a cell contains a comma in quotes. The file isn't UTF-8, so its encoding is named.
  • try: … except ValueError: continuefloat('n/a') raises a ValueError. Instead of crashing, the code skips that person. Catch the specific error you expect, not every error.
  • continue / passcontinue jumps to the next row; pass does nothing (skip just this value but keep the row).
  • if r[c].strip():Blank or space-only cells count as false, so they're skipped.
  • list(MIDLINE) + list(BILATERAL)A dictionary turned into a list gives its keys, in the order they were written.
  • out[code] = (…, len(v), stat)Stores a tuple per landmark: the value, how many people it's based on, and which statistic was used. Keeping the count lets you see when a number rests on very little data.

          
Use it anywhere: filter first, then compute; skip bad cells instead of crashing; and keep a count of how much data each answer is based on. That pattern works for survey exports, bank statements, sports stats or grade sheets.

Lesson 5
Writing files safely

          
fit_rig.py runs for minutes and writes a 44 MB file that the page depends on. If it crashed halfway through writing, you'd be left with a broken, half-written body-rig.js. Three small habits prevent that.

          
tools/fit_rig.py · banner "write" (end of file)

          
text_ = json.dumps(rig)   # (built first: a failure here must not leave a half-written body-rig.js)
with open(f'{out}/body-rig.js.tmp', 'w') as fh:
    fh.write('// Generated by tools/fit_rig.py. Body: "Male Base Mesh" (CC0) fitted to Z-Anatomy\n')
    fh.write('// (Z-Anatomy, CC BY-SA 4.0, built on BodyParts3D (c) The Database Center for Life Science).\n')
    fh.write('window.BODY_RIG = ' + text_ + ';\n')
os.replace(f'{out}/body-rig.js.tmp', f'{out}/body-rig.js')
print('wrote', f'{out}/body-rig.js', file=sys.stderr)

          
  • text_ = json.dumps(rig)Build everything before opening the file. If turning the data into text fails, nothing has been touched yet.
  • with open(…) as fh:A with block closes the file when the block ends, even if an error happens inside it. Always open files this way.
  • '….tmp'Write to a temporary name first. While it's being written, the old body-rig.js is still there and still works.
  • os.replace(tmp, final)Swap it in at the end. On the same disk, a rename happens all at once, so anything reading the file sees either the whole old version or the whole new one, never half.
  • print(…, file=sys.stderr)Progress messages go to stderr, the terminal's error channel, keeping them apart from real output.

          
Use it anywhere: any program that overwrites a file people rely on (a save file, a config, a website's data, a spreadsheet export) should write to a temporary file and os.replace it into place. It's three extra lines and prevents a whole class of "my file is corrupted" bugs.

Lesson 6
Caching slow work by fingerprint

          
Fitting each MakeHuman hand or foot takes a while, and most rebuilds don't change them. So the result is saved to disk under a name made from a fingerprint of everything it depends on. Same inputs, same fingerprint: load the saved copy. Anything changed: the name changes and it's recomputed.

          
tools/fit_rig.py · banner "hands and feet: the MakeHuman base mesh's" (≈ line 1434)

          
key = hashlib.sha1(b''.join([np.round(a, 5).tobytes() for a in (ours_, bones_P, guide)]) +
                   open(mh_parts.__file__, 'rb').read() + open(f'{MH_DIR}/base.obj', 'rb').read()).hexdigest()[:16]
cache = f'{MH_DIR}/cache/{kind}{sfx}-{key}.pkl'
was_cached = os.path.exists(cache)
if was_cached:
    P_, T_, Wp, s_ = pickle.load(open(cache, 'rb'))
else:
    P_, T_, Wp, s_ = mh_parts.fit_part(mh_mesh, sl, A_mh, ours_, joint, prox, bones_P, guide, **kw)
    os.makedirs(f'{MH_DIR}/cache', exist_ok=True); pickle.dump((P_, T_, Wp, s_), open(cache, 'wb'))

          
  • hashlib.sha1(…).hexdigest()[:16]A hash turns any bytes into a short code. Change one byte of input and the code changes completely. 16 hex characters is plenty to tell versions apart.
  • np.round(a, 5).tobytes()The inputs are arrays; their raw bytes go into the hash. Rounding first means tiny floating-point noise doesn't cause needless recomputes.
  • open(mh_parts.__file__, 'rb').read()The code itself is part of the fingerprint. Edit mh_parts.py and every cached fit is automatically out of date. This is the step people forget.
  • pickle.dump / pickle.loadpickle saves almost any Python object to a file and loads it back. Fine for your own cache; never unpickle files from someone you don't trust, because loading can run code.
  • **kwPasses a dictionary's entries as named arguments: f(**{'start': -0.1}) is f(start=-0.1).

          
Use it anywhere: a cache keyed by a fingerprint of inputs plus code never serves stale results and never needs clearing by hand. The same idea powers build tools, functools.lru_cache in memory, and the fingerprint that stops the page using a skin-uv.js built for an older body.

Lesson 7
Binary files: bytes, headers and offsets

          
Text formats like CSV and JSON are easy to read but slow and big for millions of numbers. convert_fbx.py writes meshes in a tiny binary format of its own: a 4-byte length, a JSON header, then raw numbers. meshes.py reads it back in 13 lines.

          
tools/meshes.py (the whole file)

          
def read_meshes(path):
    blob = open(path, 'rb').read()
    hl = struct.unpack('<I', blob[:4])[0]
    header = json.loads(blob[4:4 + hl])
    off = 4 + hl
    nv = sum(h['verts'] for h in header); nt = sum(h['tris'] for h in header)
    P = np.frombuffer(blob, np.float32, nv * 3, off).reshape(-1, 3); off += nv * 12
    I = np.frombuffer(blob, np.uint32, nt * 3, off).reshape(-1, 3)
    out, vo, to = [], 0, 0
    for h in header:
        out.append((h['name'], P[vo:vo + h['verts']], I[to:to + h['tris']]))
        vo += h['verts']; to += h['tris']
    return out

          
  • open(path, 'rb')'rb' = read bytes, not text. You get a bytes object you can slice like a list.
  • struct.unpack('<I', blob[:4])struct converts bytes to numbers. < means little-endian (the byte order Macs and PCs use); I is a 4-byte unsigned integer. That number says how long the JSON header is.
  • header = json.loads(…)The header is a small JSON list of parts: name, number of points, number of triangles. Mixing a readable header with raw data is a classic file design.
  • np.frombuffer(blob, np.float32, nv * 3, off)Views the bytes from off as 32-bit decimals with no copying or parsing. Then off += nv * 12 moves past them: 3 numbers × 4 bytes per point.
  • sum(h['verts'] for h in header)A generator expression: like a list comprehension inside sum(), without building the list.

          
Use it anywhere: "length, header, payload" is how PNG, ZIP, WAV and network protocols are built. When you need to store lots of numbers fast, write raw bytes with a small header describing them, and keep an off (offset) counter as you read.

Lesson 8
numpy arrays: shapes, columns and masks
numpy

          
A mesh with 80,000 points is a numpy array of shape (80000, 3): one row per point, one column each for x, y, z. Instead of looping over points, you write one expression that applies to all of them. This is the single most important idea in the Python half.

          
tools/fit_rig.py · nearest() (≈ line 540)

          
lo, hi = q.min(0) - margin, q.max(0) + margin
cand = pool[np.all((pool >= lo) & (pool <= hi), 1)]

# elsewhere in the project:
P[:, 1]                # the y (height) of every point
P[P[:, 0] > 0]         # only the points on the body's left side

          
  • q.min(0)The minimum down axis 0 (over all rows), giving one value per column: the lowest x, y and z. min(1) would give one value per row.
  • pool >= loCompares every number in pool with lo at once, giving an array of True/False of the same shape. This is a mask.
  • (…) & (…)Element-wise "and" between masks. Use &, | and ~ with arrays (not and/or/not), and wrap each comparison in brackets.
  • np.all(mask, 1)True for rows where all three columns are True: the point is inside the box on x, y and z.
  • pool[mask]Indexing with a mask keeps only the True rows. Here: only the anatomy points inside the search box, so the expensive step that follows works on a few hundred points, not 300,000.

          
Use it anywhere: "make a mask, then index with it" replaces most for-loops-with-if in data work. It's how you'd filter rows in pandas, pixels in an image, or students above a cutoff, and it's typically 50–100× faster than a Python loop.

Lesson 9
Broadcasting, and doing it in chunks
numpy

          
"Which pool point is closest to each query point?" comes up all over this project. numpy can compare every query with every pool point in one expression, a trick called broadcasting. Done all at once it would need far too much memory, so it's done in chunks.

          
tools/mh_parts.py · nearest()

          
def nearest(Q, pool, chunk=256):
    """Index of the nearest pool point for every query point (brute force in chunks, fine for a hand)."""
    out = np.zeros(len(Q), int)
    for i in range(0, len(Q), chunk):
        out[i:i + chunk] = ((Q[i:i + chunk, None] - pool[None]) ** 2).sum(-1).argmin(1)
    return out

          
  • Q[i:i + chunk, None]None adds an axis of size 1: shape (256, 3) becomes (256, 1, 3).
  • pool[None]Shape (m, 3) becomes (1, m, 3).
  • (…) - (…)Broadcasting: axes of size 1 stretch to match. (256, 1, 3) − (1, m, 3) gives (256, m, 3): every query minus every pool point.
  • ** 2 … .sum(-1)Square and add over the last axis (x, y, z): squared distances, shape (256, m). No square root needed, since the nearest is the same either way.
  • .argmin(1)For each row, the position of the smallest value: the index of the nearest pool point.
  • for i in range(0, len(Q), chunk)Chunking: 80,000 × 80,000 × 3 decimals would be about 150 GB. 256 rows at a time keeps it to a few MB, while each chunk still runs at numpy speed.

          
Use it anywhere: broadcasting turns "for each A, for each B" into one line, and chunking keeps the memory bounded. For really large sets, use a spatial index such as scipy.spatial.cKDTree; the project uses brute force where the sets are small (a hand) and box-filtering plus chunks elsewhere.

Lesson 10
Adding up by index: np.add.at and bincount
numpy

          
Triangles know their three corner points, but lighting needs a direction (normal) per point. Each point's normal is the sum of its triangles' normals. Many triangles share a point, so you need "add these values into these slots, even when slots repeat".

          
tools/mh_parts.py · vertex_normals(), smooth_field()

          
def vertex_normals(V, T):
    N = np.zeros_like(V)
    fn = np.cross(V[T[:, 1]] - V[T[:, 0]], V[T[:, 2]] - V[T[:, 0]])
    for k in range(3): np.add.at(N, T[:, k], fn)
    return N / np.maximum(np.linalg.norm(N, axis=1, keepdims=True), 1e-12)


def smooth_field(D, T, n, passes):
    i = np.concatenate([T[:, 0], T[:, 1], T[:, 2], T[:, 1], T[:, 2], T[:, 0]])
    j = np.concatenate([T[:, 1], T[:, 2], T[:, 0], T[:, 0], T[:, 1], T[:, 2]])
    deg = np.maximum(np.bincount(i, minlength=n), 1)[:, None]
    for _ in range(passes):
        acc = np.zeros_like(D); np.add.at(acc, i, D[j]); D = 0.5 * D + 0.5 * acc / deg
    return D

          
  • V[T[:, 1]]Fancy indexing: an array of indices picks those rows. T[:, 1] is every triangle's second corner, so this is every triangle's second corner position.
  • np.cross(…)The cross product of two edges points straight out of the triangle; its length is twice the area, so big triangles count more.
  • np.add.at(N, T[:, k], fn)Adds each triangle's normal into its corner's slot. Plain N[idx] += fn would lose repeats (only the last one would stick); np.add.at adds them all.
  • i, jEvery edge in both directions: point i has neighbour j. This is how a mesh becomes a graph.
  • np.bincount(i, minlength=n)Counts how often each number appears: here, how many neighbours each point has.
  • 0.5 * D + 0.5 * acc / degEach pass moves every value halfway toward the average of its neighbours: smoothing (a step of heat diffusion).

          
Use it anywhere: "group totals by ID" is everywhere: sales per customer, minutes per user, votes per candidate. np.bincount(ids, weights=values) is the fast numpy answer (pandas calls it groupby().sum()). And "average with your neighbours, repeat" smooths anything that lives on a graph or grid: images, terrain, ratings.

Lesson 11
Grouping with np.unique: thinning a mesh on a grid
numpy

          
The surface built from voxels has far more points than the browser needs. decimate snaps every point to a grid cell, merges points that share a cell into their average, and drops triangles that collapsed. It's a whole algorithm in six array lines.

  • np.c_[…, facing]Adds a column: which way the surface faces. Points in the same cell but facing opposite ways (the two sides of a thin muscle) get different keys and are kept apart.
  • np.unique(key, axis=0, return_inverse=True)Finds the distinct rows. inv says, for every original point, which distinct row (new point) it became. This "old → new number" map is the key to everything after.

Use it anywhere: "compute a key per item, np.unique(…, return_inverse=True), then aggregate with bincount" is a general group-by. Snap GPS points to a grid to make a heat map, bucket timestamps into hours, or de-duplicate rows.

Lesson 12
Functions that return functions
numpy

          
Fitting a MakeHuman hand starts by working out how to move, turn and scale it so its knuckles line up with ours. The fitting is expensive; applying the result to points is cheap. So the function does the work once and returns a new function that applies it.

          
tools/mh_parts.py · similarity(), rbf_warp()

          
def similarity(A, B):
    """Scale, rotation and shift taking points A onto B (least squares)."""
    mA, mB = A.mean(0), B.mean(0); a_, b_ = A - mA, B - mB
    U, S, Vt = np.linalg.svd(b_.T @ a_ / len(A)); D = np.eye(3); D[2, 2] = np.sign(np.linalg.det(U @ Vt))
    R = U @ D @ Vt; s = (S * np.diag(D)).sum() / (a_ ** 2).sum(1).mean()
    return lambda P: (P - mA) @ (s * R).T + mB

Lesson 15
Graphs: finding the cheapest seam

          
To flatten a sleeve, the skin map cuts it along the inner arm. "Where exactly?" is a shortest-path problem: treat mesh edges as roads, give each a cost (its length, made more expensive where a seam would be noticed), and let Dijkstra's algorithm find the cheapest route. scipy does the search; the project then walks the result back to get the path.

          
tools/uv_atlas.py · cut_path()

          
w = np.linalg.norm(V[a] - V[b], axis=1) * (cost[a] + cost[b]) / 2
G = sp.coo_matrix((np.r_[w, w], (np.r_[a, b], np.r_[b, a])), (nV, nV)).tocsr()
dist, pred, srcs = dijkstra(G, indices=np.array(src_pts), min_only=True, return_predecessors=True)
end = dst_pts[np.argmin(dist[dst_pts])]
path = [end]
while pred[path[-1]] >= 0: path.append(pred[path[-1]])

          
  • w = length × costEach edge's weight. Raising cost in some places steers the seam away from them, the way an artist would hide a seam on the inner arm.
  • sp.coo_matrix(…)A sparse matrix: an nV × nV table storing only the edges that exist. Both directions are added, so the graph is undirected.
  • dijkstra(G, indices=…, min_only=True)Distances from the nearest of several start points to every point. return_predecessors=True also gives, for each point, the previous point on its best route.
  • dst_pts[np.argmin(dist[dst_pts])]Of all allowed end points, the one reached most cheaply.
  • while pred[path[-1]] >= 0: …Path reconstruction: follow "previous point" links back from the end until you reach a start (marked −9999, which is below zero).

          
Use it anywhere: lots of problems are secretly graphs: routes on a map, prerequisite chains between courses, links between web pages, moves in a puzzle. Build the graph, pick an edge cost that says what "good" means, and let a library find the path. The cost is where your judgment goes.

    Chapter 6 · Core idea
    
      
    Bones and weights: how skin follows a skeleton
    
      
    A mesh is just two arrays: points (x, y, z for each) and triangles (three point numbers each). To animate it, every point stores up to four bone numbers and four weights that add up to 1. A point in the middle of the forearm is 100% forearm. A point at the elbow might be 50% upper arm and 50% forearm.
    
      
    Plain blending (linear blend skinning) moves the point with each bone separately and averages the results. It's fast and simple, but at a bend those averaged positions cut the corner, so the joint loses volume and pinches. The project now uses centers of rotation (Le & Hodgins 2016). The bones' rotations are blended instead, and the point turns around its own centre, which Python works out once per point. Try both below.
    
      
    
        
        
    
          
          
          
            
            
          
          
        
    
        
    Points are coloured by how much the forearm moves them: teal is all upper arm, crimson is all forearm. The faint outline is the arm at rest. "Area kept" compares the bent arm's area with the straight one; plain blending loses area at the elbow.

    Chapter 7 · Core idea
    
      
    Skin from voxels: wrapping the anatomy
    
      
    The skin isn't sculpted; it's grown from the anatomy. envelope.py drops every muscle and bone point into a 3D grid of tiny cubes (voxels, 3 mm by default), marks those cubes as "inside", grows that region outward by a few voxels for fat and skin, blurs it, and extracts the surface where the blurred value crosses one half. That last step is called surface nets. The demo does the same thing in 2D with a forearm cross-section and two fingers.
    
      
    
        
        
    
          
          
          
          
          
        
    
        
    Grey shapes are the anatomy. Push the skin layer up: gaps narrower than about twice the layer get bridged, which is right over the breastbone but wrong between fingers. "Build fingers separately" is the fix the real code uses: each finger gets its own grid, so they can't fuse.
    
      
    
      
    That's why the first hands looked like separate tubes: fingers were built apart so they'd never web together. The hands, feet and face now come from the MakeHuman base mesh instead (chapter 11), because voxels at 3 mm are too coarse for knuckles and nails.

    Chapter 8 · Core idea
    
      
    Packing the data so a browser can load it
    
      
    Python and the browser share no memory, so the arrays are written as text. Each numpy array is turned into raw bytes, then into base64 (a way of writing bytes as letters). JavaScript turns the letters back into bytes and views them as a typed array, such as Float32Array or Uint16Array, with no copying or parsing of numbers.
    
      
    Since 4 Nov, big arrays are also compressed (tools/rigpack.py). Before gzip, the bytes of each number are regrouped: all first bytes, then all second bytes, and so on. Neighbouring triangle numbers share their high bytes, so gzip finds long repeats and triangle lists shrink about 4×. An array identical to one already written (the fat and the skin share their triangles) is stored once, as {"ref": "body.index"}. The page unpacks everything once at startup with the browser's own DecompressionStream, so the rest of the code sees exactly the same bytes. That took body-rig.js from 44 MB to 20 MB. tools/pack_rig.py converts an old-format file without a rebuild.
    
      
    Positions get one more trick. Instead of 4-byte decimals, each coordinate is stored as a whole number from 0 to 65,535 inside the mesh's bounding box. That halves the size, and the step between values is tiny.

    Chapter 10 · Reuse elsewhere
    
      
    Big ideas you can take to other projects
    
      
    None of these is specific to 3D bodies. They're the habits that make this project survive constant change, and they're worth copying into anything you build.
    
      
    01
    Build once, run many
    Here: Slow, one-off work (fitting, weights, distance grids) happens in Python at build time; the browser only does what must happen every frame.
    Elsewhere: A website that pre-renders pages; a game that bakes lighting; a script that pre-computes a lookup table so the app just reads it.
    02
    One data file is the contract
    Here: body-rig.js is the only thing the two halves share. Each side can change freely as long as that file's layout stays the same.
    Elsewhere: An API between a phone app and a server; a JSON export between two scripts. Write the layout down and change it on purpose.
    03
    Generated files are never hand-edited
    Here: Never patch body-rig.js or restore it from a backup: rebuild it. The code plus the inputs is the truth.
    Elsewhere: Compiled code, exported PDFs, minified JavaScript. Fix the source, then regenerate.
    04
    Write safely, then swap
    Here: Build the text first, write .tmp, then os.replace (lesson 5).
    Elsewhere: Any save file, settings file or export that someone depends on.
    05
    Fingerprints catch stale results
    Here: The cached MakeHuman fits are keyed by a hash of inputs and code; skin-uv.js carries a fingerprint of the skin it was made for, and the page refuses a mismatch.
    Elsewhere: Build caches, downloaded data that might be out of date, "has this file changed since I last processed it?"
    06
    Think in whole arrays
    Here: Masks, broadcasting and bincount replace loops over 80,000 points (lessons 8–11).
    Elsewhere: Spreadsheet columns, image pixels, sensor logs: anything with lots of rows of the same shape.
    07
    Bound your memory with chunks
    Here: nearest() works 256 rows at a time instead of building a 150 GB table (lesson 9).
    Elsewhere: Reading a file too big for memory line by line; processing a database in pages.
    08
    Grids turn geometry into indexing
    Here: Voxels for the skin, distance grids for bones, grid snapping for decimation: "where is it?" becomes "which cell?".
    Elsewhere: Spatial hashing for collision detection in games, map tiles, bucketing times into hours.
    09
    Meshes are graphs
    Here: Edges as neighbour pairs give smoothing, heat-diffusion weights and seam paths (lessons 10, 15).
    Elsewhere: Social networks, road maps, course prerequisites. Graph tools solve all of them.
    10
    Quantise when exactness isn't needed
    Here: Positions as 16-bit whole numbers halve the file with 0.03 mm steps (chapter 8).
    Elsewhere: Storing prices in cents, audio at 16 bits, JPEG quality settings: pick the precision you need, not the most you can get.
    11
    Measure, then fix, in stages
    Here: Big changes were planned as stages with a measurement or a check in Chrome between each one, so a bad step is caught early and easy to undo.
    Elsewhere: Any change you can't easily see working: split it, check each part, keep a way back.
    12
    Comments say why, banners say where
    Here: Section banners like # ---- skin weights by heat diffusion make a 3,000-line file navigable; comments explain reasons and sources (skinfold studies, ANSUR II), not what the line obviously does.
    Elsewhere: Any code someone (including future you) will read in six months.

    Muscle contraction
    In the code
    
          
    Python fit_rig.py · "muscle contraction" (≈ line 3037) stores each muscle's attachments · Browser contract() bulges it every pose
    
          
    A muscle keeps its volume. When its two ends get closer, its belly gets fatter; when it's stretched, it gets thinner. Flexing adds more on top (the idea comes from Scheepers et al. 1997). Length is measured between the attachment points, not from a joint angle, because muscles like the biceps, rectus femoris and gastrocnemius cross two joints.
    
          
    
            
            
    
              
              
              
            
    
            
    Crimson is the biceps (front of the arm), teal the triceps (back). Bend the elbow: the biceps' ends come closer, so it gets shorter and fatter; the triceps is stretched around the elbow, so it thins. Belly thickness follows 1 ÷ √(length ÷ rest length), which keeps the volume constant, and Flex adds up to 35% more.
    
          
    
          
    
            
    
              
    Built once in Python
    
              
      
                
    • Each muscle's two attachment ends, which rig bone carries each, and its rest length.
      • 
                
    • Per point: how far along the muscle (0–1), which way is "out", how far out, and a belly weight that's 0 at the tendons and highest in the middle.
      • 
                
    • Fan muscles (deltoid, pectoralis major, lats, trapezius): length per point, from that point's own origin to the insertion, so each part acts on its own.
      • 
              
    
            
    
            
    
              
    Every pose in the browser
    
              
      
                
    • Stretch = current length ÷ rest length; push each point out by (1/√stretch − 1) × its distance out × belly weight, clamped.
      • 
                
    • Runs after skinning, before collisions and clean-up.
      • 
                
    • The skin and fat get the same offsets through RIG.anchors, even with muscles hidden, so a tattoo on the biceps stretches with it.
      • 
                
    • The Flex slider (0–1, default 0.3).
      •

    Modelled hands, feet and head (MakeHuman)
    In the code
    
          
    Python tools/mh_parts.py · fit_rig.py banners "hands and feet: the MakeHuman base mesh's" (≈ line 1380) and "head" (≈ line 1469) · assets/makehuman/
    
          
    The old hands were a WebXR palm with separate finger tubes, the toes were tubes too, and the face was an even wrap that looked gaunt. All three now come from the MakeHuman base mesh (CC0), which has knuckles, webbing, nails, toes, eyelids, lips and a nose tip, fitted onto the real anatomy. Lessons 6 and 12 in the Python course walk through parts of this code.
    
          
      
            
    1. Rough alignment. Matching landmarks on both (wrist, knuckles and fingertips; ankle, heel and toes; skull landmarks for the head). similarity() finds the best move, turn and scale, then rbf_warp() bends it smoothly so every landmark lands exactly.
      2. 
            
    2. Fine fit. A smooth offset nudges the part toward the old surface (a rough guide for thickness) and out of the bones, so it keeps its own detail but sits on our anatomy.
      3. 
            
    3. Join the body. The body is cut at a ring (wrist, ankle, neck), the part at a matching ring, and the gap is bridged with a strip of triangles. The joins are sized to an average man from ANSUR II measurements.
      4. 
            
    4. Keep the layers in step. The fat surface and the skin share point numbers, so the new parts get a matching fat surface and anchors.
      5. 
            
    5. Cache the result. Each fitted part is saved under a fingerprint of its inputs and of mh_parts.py itself, so rebuilds skip the slow fit unless something changed.
      6. 
          
    
          
    
            
    Hands
    Fitted to the hand bones, both sides. Keeps the knuckles, the webbing (fingers joined only near their base) and the nails.
    
            
    Feet
    Fitted to the foot and toe bones, with both soles flat on the same floor. Keeps toenails and separate toes past their base.
    
            
    Head
    Fitted to the skull with soft-tissue depths at about 30 landmarks, which tissue_depth.py pools from the C-Table (19 studies, 1,971 people). Eyes and mouth are closed, keeping a natural, normal-looking face.
    
          
    
        
    

      
    
      
    
    

    
    
    
      
    Chapter 12
    
      
    Working with Claude on this project
    
      
    Most of the time a change is lost to vague location ("the arm looks off"). The most useful thing you can give is where, when and which half. Use the vocabulary in this guide: a pose name, a layer, a body part, a file and a section banner.
    
      
    Describe what you see
    
      
      
        
    • The pose: a preset (A-pose, Standing, Star, Reach, Hands behind head) or what you dragged, and roughly how far.
      • 
        
    • The layer: Skin, Adipose, Muscles + cartilage or Skeleton, and the Flex setting if muscles look off.
      • 
        
    • The exact pose: press Copy pose and paste it into your message, so the same pose can be loaded with Paste pose.
      • 
        
    • The spot: anatomical names help: inner elbow, wrist crease, armpit, lower back.
      • 
        
    • At rest or only when posed? At rest points to Python (shape). Only when posed points to the browser (movement).
      • 
        
    • What it should look like: a reference photo or one sentence on what "right" is.
